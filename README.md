# Перевод с русского на английский: Seq2Seq LSTM

Учебный ML-проект на PyTorch. Цель — сравнить три варианта переводчика: LSTM со словарём слов, LSTM с BPE-токенизацией и LSTM с BPE и механизмом внимания Bahdanau.

В проекте есть подготовка данных, обучение моделей, сравнение на общей тестовой выборке, ручной разбор 30 переводов и демо на Streamlit.

## Результаты

Сохранённые результаты из [test_bleu_comparison.csv](results/test_bleu_comparison.csv):

| Модель | BLEU ↑ |
| --- | ---: |
| LSTM со словарём слов | 44.38 |
| LSTM + BPE | 42.79 |
| LSTM + BPE + attention | **48.96** |

Все модели оценивались на одних и тех же 82 408 тестовых парах. Использовались SacreBLEU, токенизация `13a`, учёт регистра и один эталонный перевод на пару. Генерация — greedy decoding с лимитом 50 токенов.

В этом эксперименте BPE без attention не улучшил BLEU относительно словарной модели. Лучший результат получила модель с attention: на 4.58 пункта выше словарной LSTM. Она используется в демо. Это результат конкретных запусков: устойчивость различий по нескольким seed не проверялась.

## Данные

Исходный файл — `data/dataset_small.tsv`: 824 903 пары, четыре столбца без заголовка — `ru_id`, `russian`, `en_id`, `english`. Для обучения используются тексты на русском и английском.

Обработка в `src/preprocessing.py` включает нормализацию Unicode NFKC и пробелов, удаление пустых строк и повторяющихся пар, фильтрацию предложений по длине от 1 до 30 слов с каждой стороны. После обработки остаётся 824 074 пары.

| Выборка | Число пар |
| --- | ---: |
| Train | 659 259 |
| Validation | 82 407 |
| Test | 82 408 |

Разбиение выполняется через `train_test_split`: сначала 80% на train, затем оставшиеся данные делятся поровну на validation и test. В обоих вызовах `random_state=39`, `shuffle=True`.

Словари строятся только по train. Для word-level модели используется частотный словарь с `min_freq=2`. Для BPE — отдельные токенизаторы SentencePiece для русского и английского, по 8 000 токенов, `character_coverage=1`.

Источник предложений — [Tatoeba](https://tatoeba.org/). В проекте используются русско-английские пары с предобработкой, описанной выше.

Файл `data/dataset_small.tsv` скачан из Tatoeba как выгрузка пар предложений на русском и английском языках. Новая выгрузка Tatoeba может отличаться по составу и порядку строк, поэтому для точного повторения разбиения нужен исходный файл проекта.

## Обучение

В текущих ноутбуках используются следующие настройки:

| Параметр | Значение |
| --- | --- |
| Размер эмбеддинга | 256 |
| Размер скрытого состояния LSTM | 256 |
| Число слоёв LSTM | 1 |
| Dropout | 0.2 |
| Batch size | 64 |
| Оптимизатор | Adam, learning rate `1e-3` |
| Число эпох | 10 |
| Teacher forcing при обучении | 0.5 |
| Gradient clipping | 1.0 |
| Seed | 39 |

Функция потерь — CrossEntropyLoss с игнорированием padding. Чекпоинт каждого запуска выбирается по минимальному validation loss; при валидации teacher forcing отключён. Затем сохранённые модели сравниваются по BLEU на test.

## Запуск готового переводчика

Из корня проекта:

```bash
python -m pip install -r requirements-demo.txt
python -m streamlit run app.py
```

Для демо нужны `models/best_bpe_attention.pt` и соответствующие ему `artifacts/tokenizers/ru_bpe.model`, `artifacts/tokenizers/en_bpe.model`. Датасет и повторное обучение не требуются. Приложение использует CUDA, если она доступна, иначе CPU.

Подробности запуска, пример вызова из Python и ограничения — в [docs/demo.md](docs/demo.md).

## Повторение экспериментов

Команды и ноутбуки выполняются из корня проекта. Для работы в отдельном окружении:

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

В Linux или macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей и запуск JupyterLab:

```bash
python -m pip install -r requirements.txt
python -m jupyterlab
```

1. Поместить `dataset_small.tsv` в папку `data`. Изменение состава или порядка строк изменит разбиение и результаты.
2. Для обучения BPE-моделей с нуля выполнить `python -m scripts.train_bpe_tokenizer`. Скрипт обучает токенизаторы только на train и записывает их в `artifacts/tokenizers/`. При использовании готовых BPE-весов этот шаг пропускается: токенизаторы должны соответствовать весам.
3. Выполнить нужные ноутбуки обучения сверху вниз: `01_lstm_word_baseline.ipynb`, `02_bpe_lstm_baseline.ipynb`, `03_bpe_attention_lstm.ipynb`. Для обучения только модели с attention достаточно `03`. После работы с каждой моделью закрыть её ядро, чтобы освободить память.
4. Для сравнения всех моделей открыть `04_model_comparison.ipynb` в новом ядре. Он заново выделяет test с тем же seed и последовательно загружает три чекпоинта из `models/`, считает BLEU и освобождает память после каждой модели. Результаты сохраняются в `results/test_bleu_comparison.csv`.
5. Для ручного разбора переводов выполнить [05_error_analysis.ipynb](05_error_analysis.ipynb). После замены модели ручные оценки нужно пересмотреть: сохранённые комментарии относятся к текущим переводам.

Ноутбуки обучения сохраняют лучшие веса в `models/`. Повторный запуск обучения заменяет одноимённые файлы, а скрипт токенизации заменяет токенизаторы. Для нового эксперимента следует заранее сохранить прежние веса вместе с их токенизаторами.

Для сравнения в `04` нужны все три файла: `best_seq2seq_baseline.pt`, `best_seq2seq_bpe_baseline.pt`, `best_bpe_attention.pt`. В `.gitignore` из весов оставлен для публикации только чекпоинт демо. Остальные нужно получить отдельно или обучить в `01` и `02`.


## Анализ ошибок и ограничения

В [05_error_analysis.ipynb](05_error_analysis.ipynb) собраны 30 вручную подобранных примеров с эталонным переводом, результатом модели и оценкой смысла и грамматики. Это набор для разбора ошибок, а не случайная выборка для оценки их частоты.

На этих примерах модель правильно переводит часть коротких бытовых фраз, вопросов и отрицаний. Основные ошибки — повторы и пропуски слов, искажение чисел и времени, буквальный перевод идиом. Например, `Мне пора идти спать.` переводится правильно, а без завершающей точки получается `I was time for go to bed.`

Ограничения оценки:

- В 17 892 строках test (около 21.7%) русское предложение встречается также в train с другим английским переводом. Разбиение выполнено по парам, а не по уникальным русским предложениям. Результат не следует трактовать как оценку исключительно на новых исходных фразах.
- Test использовался для итогового выбора модели. Дальнейшие настройки следует подбирать по validation, а независимую итоговую оценку проводить на отложенных данных.
- Корпусный BLEU не гарантирует правильность каждого перевода. Допустимая формулировка также может отличаться от единственного эталона.
- Перевод длинных текстов и текстов из других областей отдельно не оценивался.

По ручному разбору нельзя точно установить причины каждой ошибки. Влияние состава данных, архитектуры и способа декодирования потребует отдельных экспериментов.

- Проверить выбор чекпоинта по validation BLEU вместо loss.
- Добавить варианты пунктуации в обучающие данные и проверить устойчивость перевода.
- Повторить эксперименты с несколькими seed; отдельно сравнить результат с небольшой Transformer-моделью.
